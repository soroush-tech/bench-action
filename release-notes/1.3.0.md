## bench-action@1.3.0

Report-only mode for runs that must not fail on speed, such as a release report, and every
report now goes to the job summary too (#14). Existing workflows need no change: with
`min-ratio` set, the gate works as before.

### Features

- **`min-ratio` is optional.** Left empty, the action reports each case's ratio without a
  gate: the head line reads `` Baseline case: `x` · report only, no gate ``, and no case is
  marked ❌ for being slow. A run that crashed, or left no results to compare, still shows ❌
  and fails the job. A `min-ratio` that is given must still be a positive number.
- **Job summary.** Every run writes the report to its job summary, with or without a pull
  request, so a release run gets its report with no extra wiring. The `report` output is
  unchanged.
- **What produced the numbers.** Under the head line, the report names the bench version,
  Node version and sandbox limits of the run, for example
  `soroush-bench 2.4.0 · node v24.22.3 · cpus 1 · cpuset 0 · memory 512m`.

### Changed

- A file whose run passed but left no results to compare is now a failure (❌, and the job
  fails) in both modes. In 1.2.x it showed ✅. With the gate on, this happens only when the
  sandbox itself is broken, as in 1.2.0.

### Internal

- Re-vendors `@soroush.tech/bench` **2.4.0** and re-syncs `src/sandbox` from it: each run
  passes the sandbox limits as `--sandbox-env`, so the results record them
  (soroush-tech/core#362).
